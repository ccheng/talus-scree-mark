# Independent M2 acceptance

`fixtures.py` rasterizes the candidate blank PDF at 144 DPI and verifies its published profile digest. It uses independently generated answer patterns, position and status oracles, geometric transforms, and seeded failures. The renderer does not import the application recognition engine. Generate the public, synthetic acceptance set with `python3 tests/acceptance/m2/fixtures.py app`. This requires Pillow and `pdftoppm`. The generated images and oracles are disposable and ignored by Git.

- Twenty standard sheets have distinct answer patterns and cover all four right-angle rotations, modest scale, translation, and perspective. The geometry oracle projects eight independently positioned check landmarks plus every bubble center through the fixture transform. Error is divided by the local projected bubble radius.
- The stress set includes absent and clipped registration features, a changed identity, mirror, clear double marks, convention-invalid NR literals, a covered item and characterized quality perturbations. Blocking negative cases have exact retake or item-review expectations. Other perturbations exercise the engine's response to degraded evidence.
- `browser.mjs` runs the recognition module over JPEG pixels decoded in desktop Chromium, separately exercises normal UI/worker paths, and checks result invalidation, local storage, request logs and desktop-simulated offline reopening. It shares the existing M1 fixture server. Run `node tests/acceptance/m2/browser.mjs "$PWD/app"` with `TALUS_TEST_PLAYWRIGHT_PATH` set to the installed Playwright `index.mjs`, or with Playwright available to the workspace. The workflow installs the development-only dependencies on its runner.
- This is deterministic acceptance. Sealed benchmarks and physical iPhone Safari and Home Screen evidence are recorded separately. M1 browser regressions run in the existing M1 workflow.
