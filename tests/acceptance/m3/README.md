# Independent M3 acceptance

Generate the synthetic forms with `python3 tests/acceptance/m3/fixtures.py`. This uses Pillow and no application code. The forms have independent response maps and known geometry for translated, scaled, skewed and rotated captures. The disposable output is ignored by Git.

M3.2 reclassifies the historical `wrong-same-grid` images and three interleaved title or instruction variants as compatible in an explicitly confirmed batch. The generator retains image bytes and recovers the original response marks from seed 53 for the three same-grid examples and seed 47 for the title, missing-title and instruction variants. Before changing the oracles, an archived M3.1 generator was used to compare each JPEG against a normal-print control generated with the same seed, transform and encoder. All 21 response-block crops across the six JPEGs were pixel-identical, and the ordered item, choice and slot maps were unchanged. The interleaved `wrong-same-grid` digest was identical on both sides of the change. The generator now also asserts pre-encoding response-crop identity. A paired name-field case holds the response image and literal oracle fixed while altering strokes outside the response regions.

Required structural negatives include missing blocks, a displaced complete block, a missing row, an extra row within the response footprint, an extra row continuing the enrolled grid, incompatible choice-column spacing, clipping, mirroring and a geometry-symmetric page with unresolved orientation. The new continuation row follows the original column positions and row pitch just after the enrolled block. The spacing variant shifts one complete interior choice column while preserving the page bounds, title, row count, other grid blocks and response marks. The test supplies accurate corners to applicable structural negatives to verify that manual orientation cannot waive a structural check. Clear double marks still require review. The batch worker test covers required attestation, revision pinning across captures, explicit end and reopen, stale result invalidation, no inferred key and offline reuse without retaining student images or answers.

Automatic blank discovery uses the three published blank and marked pairs with neutral upload names. The normal tests make zero geometry edits, use one successful overlay confirmation, validate the complete stored block, item and slot maps, and compare the paired marked-sheet observations exactly. Timings cover scripted blank selection to a visible proposal and to saved setup. An independent four-box form includes decimal positions above and below digit rows and checks explicitly supplied descending symbol order without repositioning bubbles. Another independent blank has one obscured ring inside a required lattice. It checks that review blocks automatic saving, then verifies explicit correction against its clean marked counterpart. These are desktop browser checks. They do not measure teacher or iPhone setup time.

The blank and marked pair checks preprinted ink, both decimal positions, an unmarked numerical response and a competing pencil mark. Run `python3 tests/acceptance/m3/alberta-photo-fixtures.py` for the separate camera-like case with tall, shared box dividers, perspective, shading, blur and JPEG compression. Both fixtures check that renumbering preserves bubble coordinates. Chromium touch input checks that the canvas region repaints during the drag and commits its coordinates when the touch ends.
