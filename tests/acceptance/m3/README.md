# Independent M3 acceptance

Generate the synthetic forms with `python3 tests/acceptance/m3/fixtures.py`. This uses Pillow and no application code. The forms have independent response maps and known geometry for translated, scaled, skewed and rotated captures. The disposable output is ignored by Git.

M3.2 reclassifies the historical `wrong-same-grid` images and three interleaved title or instruction variants as compatible in an explicitly confirmed batch. The generator retains image bytes and recovers the original response marks from seed 53 for the three same-grid examples and seed 47 for the title, missing-title and instruction variants. Before changing the oracles, an archived M3.1 generator was used to compare each JPEG against a normal-print control generated with the same seed, transform and encoder. All 21 response-block crops across the six JPEGs were pixel-identical, and the ordered item, choice and slot maps were unchanged. The interleaved `wrong-same-grid` digest was identical on both sides of the change. The generator now also asserts pre-encoding response-crop identity. A paired name-field case holds the response image and literal oracle fixed while altering strokes outside the response regions.

Required structural negatives include missing blocks, a displaced complete block, a missing row, an extra row within the response footprint, clipping, mirroring and a geometry-symmetric page with unresolved orientation. The test supplies accurate corners to applicable structural negatives to verify that manual orientation cannot waive a structural check. Clear double marks still require review. The batch worker test covers required attestation, revision pinning across captures, explicit end and reopen, stale result invalidation, no inferred key and offline reuse without retaining student images or answers.

Generate the alternate-renderer stress input with `pdftoppm -f 1 -l 1 -r 180 -png -singlefile app/fixtures/m3/mc-only-filled.pdf tests/acceptance/m3/fixtures/cross-renderer-filled`. Any accepted responses are compared with the public key. A retake is reported as stress coverage, apart from the same-print correctness gates.

Run `node tests/acceptance/m3/frozen-reference.mjs app` to verify accepted M2 reference compatibility inputs. Existing M1 and M2 workflows separately test their normal entry points when app files change.

The M3 workflow runs `node tests/acceptance/m3/browser.mjs "$PWD/app"` on desktop Chromium with the `TALUS_TEST_PLAYWRIGHT_PATH` pointing to Playwright. It verifies authoring, markerless recognition, saved revisions, and browser workflow. Counts and conservative review/retake outcomes are reported separately from silent errors. Desktop checks use synthetic inputs and desktop offline simulation. They do not establish real iPhone acceptance, recognition generalization, or physical timing.
