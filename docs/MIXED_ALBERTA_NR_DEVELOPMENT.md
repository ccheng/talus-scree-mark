## Authoring

Use the existing whole-page proposals as a starting point. Check the overlay,
especially near faint NR fields where discovery can propose extra MC rows.
For an incomplete NR question, use a single box that includes the writing
boxes, inner decimals and ten rows of digits. **Find Alberta NR bubbles**
uses the existing bounded detector first, then the local-outline recovery
studied in Stage 5. If a usable grid remains incomplete, **Place NR grid with
four taps** fits the left 0, right 0, left 9, and left decimal while preserving
compatible detected positions. Compare every estimated ring with a printed
bubble before accepting estimates. The existing individual-position editor
remains available. A template revision recalibrates printed NR ink using the
blank that was imported for that revision.

Independent mobile-emulated Chromium authoring on `525af2d` saved 32/32
MC and 84/84 NR reference centers and preserved the mixed mapping through
reload, reimport and a revision. A faint block needed all four taps. Refitting
a partial proposal preserved 41 observed positions and left one unresolved
estimate. A box spanning two NR questions was rejected.

## Recognition limits

The independent recognition reserve used eight synthetic valid completed
captures, independently transformed from the blank, and a shifted-row control.
Both automatic and manually placed corners registered all eight valid captures
and refused the shifted layout. Every path read all 64 MC answers exactly.
Of 16 NR observations per mode, 8 automatic and 14 manual matched the expected
literal and review state exactly. The other observations were held for review.
This includes unnecessary review on some blank slots or strong marks when dark
printed digits behave like competing marks, and some malformed answers held
without a full literal. The final candidate explicitly reviews captured leading
zeros such as `004 ` while keeping the original four-slot literal. One denser
sampling experiment suppressed a weak pencil mark during independent testing and
was removed. The established mark thresholds and geometry gates remain in use.

## End-to-end verification

On exact application build `f0ecaee1737929c4275ec27e`, the Independent Tester
enrolled 8 MC and 2 Alberta NR questions in the GUI, set their key and
proficiency/outcome categories, and graded two newly posed synthetic captures.
The first scored 10/10. The second scored 6/10 with two pending reviews
(invalid leading zeros and a double mark), then 7/10 with one pending and
8/10 final after the corrections. Four category intersections reconciled at
each step. Saved reload and clean-context backup restore preserved the scan
photo, original observations and review history. CSV subtotals and JSON
backup were verified.

These are synthetic and desktop Chromium results. Physical iPhone Safari
acceptance and production integration require separate approval.
