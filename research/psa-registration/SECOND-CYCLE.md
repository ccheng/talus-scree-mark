# Second registration research cycle — automatic enrollment and compatibility

## Scope
This extends the authorized REG-R1–R8 initial work. Production baseline remains 896cabc04ecb2a468a0a76d0b69a117afc73d855, release 17240ea326d6d2fe470c5270. No application changes, no private assessment photographs, no real student data, no model training.

Four versioned experiments, each with its exact JSON results:
- auto-enrollment.mjs: pixel-based distributed landmark selection, internal NR bitmap digits and decimals, actual NR blank-ink calibration, bounded model, mark reading.
- no-boundary.mjs: remove contrast between page and background; distinguish absent print from conflicting visible print; narrow fallback for obscured landmarks.
- pose-hypotheses.mjs: alternative inset image-frame seeds when detected corners are poorly corroborated.
- digit-identity.mjs: semantic verification of unfilled internal printed NR digits against template patches; current best experiment.

Run from repository root:
```
node research/psa-registration/auto-enrollment.mjs
node research/psa-registration/no-boundary.mjs
node research/psa-registration/pose-hypotheses.mjs
node research/psa-registration/digit-identity.mjs
```
The harnesses import the actual pinned app code. Results were generated by executing those functions with the pinned app modules loaded in a JavaScript isolate; the command-line Node reproduction was not separately executed. No timings should be extrapolated to mobile. These four suites overlap; do not sum their counts.

## Best current development results (digit-identity)
One synthetic mixed sheet: 14 MC items across two blocks (63 bubbles), two NR items across two blocks (84 bubbles), 147 total centers. Automatically enroll 16 external printed landmarks, four per block, from a clean canonical blank raster and known saved block bounds. No supplied landmark coordinates in the selection function. All 84 NR positions get printed blank-ink calibration. Rendered glyphs are simple 5x7 bitmap digits and decimals, not a representative font corpus; enrollment uses exact clean synthetic blank raster, not a photographed blank.
- Valid capture cases: candidate 10/10 registered vs existing 4/10. All 160 candidate response observations match the specified status/rawText, including blanks, multiples and decimals; this is actual app mark reader execution, not scoring, correction workflow, persistence or final grade verification. Each accepted capture uses canonical rectification and the existing geometry gate with canonical corners.
- Incompatible controls: candidate 6/6 withheld vs existing 3/6 withheld. Existing accepted adjacent extra row, changed explicitly designated identity labels, and permuted NR digits in identical geometry. Identity labels in this artificial test are defined as required; the existing app intentionally allows incidental text changes. Do not classify arbitrary print changes as wrong layout.
- Borderless: no edge contrast, detected corners nevertheless proposed, only 8 and 7 of 16 matched. Generic 3% inset frame seed recovered 16/16 in both. Initial P95 center error 29.726 and 28.830 source pixels; after correction 0.325 and 0.425. No supplied true corners used for these cases. This is a bounded seed search, not general rotation/crop/multi-sheet global registration.
- Obscured labels: 14/16 matched, two absent patches, no contradictory print, existing accepted. Narrow fallback accepted and 16/16 responses matched. Do not fall back when conflict evidence is present.
- Relocated MC/NR blocks (including labels) withheld, as were adjacent extra row and changed designated labels.
- Permuted NR control: identical bubble coordinates, all ten digit labels cyclically shifted by three in one NR grid. 35/37 readable unfilled digit positions flagged; 3 masked by fill. Other grid zero conflicts. Valid ten-case suite has two isolated digit mismatches (one each on two deformed cases), no column has three. Threshold is a provisional 3 conflicts among >=5 checked in a slot. The prototype compares patch distances to other digits in the same slot, excludes dark fills and weak matches. This is not general OCR or full MC/NR semantic identity. Verify with distinct fonts, real printed digits, varied fill and displaced labels before adoption.

## Model and uncertainty
Candidate compares affine, projective and regularized quadratic correction fitted to training landmarks with fixed held-out landmarks. Uses simplified sampled deformation bounds: max displacement 18 pt, min Jacobian determinant .8, max Frobenius deviation from identity .18; these are development thresholds, not a proof of physical plausibility. Pose seeds ranked by matched landmark count before held-out correction; alternate hypotheses are not fully enumerated or all independently validated. Local block translations are diagnostics only, never separate unconstrained block corrections. Existing response geometry is rechecked after rectification. Additional adjacent-row guard is not scope-aware yet. Identity gate currently uses local print contrast and correlation; missing and conflicting evidence are distinct. Exact identity cannot be inferred from geometry alone.

## Remaining research / deployment gates
Not ready for LSDE integration or deployment. New cycle should prioritize independently authored heterogeneous layouts and real-looking photos, photographed blank enrollment and saved landmark contract, rotation/mirroring/cropped and multiple-sheet ambiguity, robust multi-hypothesis ranking and held-out coverage, repeated patterns and false associations, strict global pose and nonlinear fold/extrapolation bounds, MC choice/number semantics and NR glyph verification including weak or partial marks, exclusion and partial-scope semantics, item-level uncertainty, scoring and regression through actual product integration, browser/offline/mobile performance. Need compare actual deployed full automatic paths and manual-corner paths on a held-out suite. Preserve existing fallback and batch authorization, never silently accept a semantic conflict. No additional model training currently warranted.
