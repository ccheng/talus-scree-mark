# PSA MC structured discovery — MC-R9–R16 development cycle

Research-only Python reference extending MC-R1–R8. No production code, deployment, student-mark grading, or profile schema changes. Self-evaluated development fixtures, not independent or blinded validation. Earlier research branch base: `7800d3f7b8d038b6942a60c8a13de00f81e62ae6`.

## Reproduce

Python dependencies: numpy, scipy, opencv-python, Pillow, joblib, scikit-learn. Generic system font paths are in `glyphs.py`, `cycle2.py`, and `final_check.py`. Font availability/version affects reproduction. `OPENBLAS_NUM_THREADS=1` was set for runs. No private images included. Do not load untrusted pickle files.

- `python cycle2.py`: first-cycle vs independent number/joint path, 12 synthetic development pages.
- `python extension.py`: independent header path and perspective tests using known inverse homographies.
- `python affine_check.py`: optional local affine refinement on 12 sheared synthetic pages; disabled by default in combined engine.
- `python final_check.py /path/to/trusted-regenerated-svm.pkl`: final combined path, header recovery, and prior NR SVM vs template digit classification. Optional second argument is a local private photo; only aggregate results are emitted. The model comes from the prior PSA NR R13–R16 portable research archive (`portable/regenerated-svm.pkl`). No model retraining needed.
- `python nr_check.py /path/to/portable /path/to/trusted-regenerated-svm.pkl`: cross-type reconciliation using `nr_reference.py` and `dev_fixtures.py` from that same trusted archive. Those files and the model are not duplicated here.

JSON files contain actual outputs; run times reflect the development environment only. In all row scoring, a geometry match requires matching choice count, all centers within 4 raster pixels, and one-to-one row assignment. This does not verify every recognized question number or real-world answer extraction. `confirmed` is an internal research classification, not permission to save a production template.

## Results

- R9–R12: independent OCR token grouping and dynamic-programming integer chains, candidate 4/5-column hypotheses with origin shifts, independent header row search, conservative union. On 12 labelled synthetic development pages, R1–R8 mapped 167/168 true rows, 4 false proposals (2 confirmed); combined engine mapped 168/168, 161 confirmed and 7 provisional, plus 4 false proposals all review-only. The two gap-ring variants each retain two false proposals for review. A separate no-number/one-missing-bubble-per-row page recovers 14/14, all review-only, versus 0/14 in R1–R8 and number-led joint path. No inferred point is automatically confirmed. Missing whole rows require consecutive supported labels on both sides. The latter rule fixed a private-photo duplicate OCR endpoint in the second cycle; final known private-photo aggregate is 14 rows with numbers 1–14, no review. Not a fresh independent photograph or exact coordinate oracle. Missing wholly unobserved endpoint rows are deliberately not reconstructed automatically.
- R13: actual previous NR Python reference on two synthetic pages with 22 true unnumbered MC rows each. Four valid NR groups on first page, one valid and three malformed NR groups on second. All 44 true MC rows mapped; 8+3 false MC proposals overlap NR geometry. All 11 are review-only after reconciliation, no automatic deletion. Rejected NR proposals can challenge MC only with strong corroboration (support >=32, header >=0.30, >=7 correct SVM digit rows, axes <=0.25), or accepted NR. These development thresholds are not validated on independent sheets. NR reference outcomes: five valid grids accepted with exact 42-point correspondence under its own criterion; two invalid review and one reject. Existing MC proposals are preserved for review rather than silently suppressed.
- R14: strong synthetic perspective: 39/56 rows mapped before rectification, 56/56 using ground-truth inverse homography. This is not autonomous corner detection. Optional local affine fit from observed centers: 164/168 before, 168/168 after on 12 sheared pages. No false confirmed rows after affine on this suite. Affine option remains disabled in `combined.py` pending additional evidence.
- R15: 480 presegmented synthetic digits from four font families, contrast/blur/noise variations. Prior NR SVM 432/480 (90%), HOG templates 416/480 (86.67%). By rendering size 9,13,20,30: SVM 86,111,117,118; template 70,109,117,120, each /120. Font independence from NR training not established. Not end-to-end OCR; not evidence that the SVM improves full-page MC detection. The MC engine continues to use template matching, not the SVM.
- R16: first-cycle comparative and ablation evidence recorded, not a fresh native deployed-detector comparison or independent evaluation. Twelve final combined runs approximately 0.18–0.31 s desktop development time, excludes glyph bank generation and NR reference execution. No phone performance claim. Same development suite used for tuning and testing. Need independent fixtures (especially ambiguous numbering, NR lookalikes, cross-block overlap, absent headers, unusual choice labels, perspective errors and false positives), compare to actual deployed detector, preserve provenance, then decide on native port. No optimization or deployment authorized or undertaken here.
