# Milestone roadmap

M0 and M1 are accepted and merged. The [M2 specification](docs/MILESTONE_2_SPECIFICATION.md) is approved for implementation after SWE Director review. Acceptance and merge require separate Product Owner approval. Recognition targets below are provisional engineering targets. Finalize criteria with the Product Owner and SWE Director Assistant before implementing each milestone. Keep each milestone independently reviewable and record exact build and evidence in its PR. User-facing milestones require a directly accessible HTTPS GitHub Pages preview for mock data at [the development URL](https://ccheng.github.io/talus-scree-mark/). Evaluate a dedicated, isolated HTTPS origin before real student-data use.

| Milestone | Scope | Proposed acceptance |
| --- | --- | --- |
| M0 Foundation | Architecture, QA and research proposals, Node fixture harness | README, contributor instructions, handoff, roadmap and quality gate agree. Fresh-checkout `npm test` succeeds. Synthetic fixture provenance and limits are explicit. PR review required. |
| M1 Offline capture shell | App shell, install readiness, offline cache and update, transient local image capture/import | At project subpath, install online then cold-launch and capture/import in airplane mode on a named iPhone in Safari and Home Screen modes. Exercise permission denial/recovery, documented image formats and orientation, missing assets and interrupted update. Verify capture data stays in memory and the app attempts no transfer. |
| [M2 Alignment and fixed-layout MC/NR OMR](docs/MILESTONE_2_SPECIFICATION.md) | One synthetic reference layout, registration and mark classification | Verify accepted alignment within a preregistered ROI tolerance, an exact oracle for every MC and NR fixture including blanks/decimals/zeros, and all seeded unmistakable double marks, clipped anchors on the anchored reference layout and wrong profiles routed to review or retake. On standard captures target ≥95% auto-coverage and ≤0.5% wrong among auto-accepted responses separately for MC and NR. Target scan-to-review p95 ≤3 s on the reference phone. |
| M3 Reusable per-test layouts | Versioned local profiles, including a registration path for existing sheets without printed anchors or IDs | Read at least three distinct registered layout families, including an anchor-free example and a newly registered family with frozen recognition settings. Evaluate blank-sheet import with teacher-confirmed regions or manual calibration for anchor-free registration. Verify stable region-to-item mapping, report holdout results by family and registration path, and block seeded cases with a wrong or unconfirmed profile. |
| M4 Review, grading and export | Corrections, key entry, local persistence, versioning and CSV/JSON exports | Pass all preregistered grade/precision/key-oracle and audit-roundtrip cases. Preserve raw results through correction, rescan, reopen and export. Unkeyed or unresolved items show explicit status. Verify deletion/quota behavior, CSV interpretation and local export on iPhone. |
| M5 Optional handwriting and comparison | Same-origin offline CNN, local comparison and review | Target ≥90% exact clear four-character tokens on oracle crops, with full-pipeline recognition reported separately. Route every seeded bubble/handwriting mismatch or unsupported symbol to review. Demonstrate bubble-only flow when model files are missing. Target optional OCR p95 ≤5 s on approved reference hardware. Keep handwriting advisory until a later decision based on measured risk. |
| M6 Pilot and hardening | Classroom-scale workflow, readability, latency and data lifecycle | Run approximately 30–40 distinct mock answer sheets. Optionally use seven sheets for an earlier smoke test. Exercise offline operation and a reconnect or relaunch interruption. Report throughput, review load, failure and retry counts, privacy checks and a local backup/restore drill on named phones. A classroom-scale pilot establishes workflow evidence with uncertainty. |
| Follow-on recognition research | Automatic discovery of MC and NR components while keeping registered profiles available | On unregistered held-out layouts, measure component type, extent, grouping and item/cell correspondence separately from mark recognition. Route uncertain discoveries to teacher confirmation. Specify acceptance targets after initial feasibility evidence and separate approval. |

For M2 and later, specify fixture counts and per-stratum denominators, calibrate only on the calibration split, and use a protected held-out set. Report sample sizes at both response and independent cluster levels, the uncertainty method, clustered observations, and observed silent-error numerators and denominators. Crossing a provisional target or observing zero errors on a small sample does not establish statistical reliability. See [research and benchmarks](docs/RECOGNITION_RESEARCH.md).
