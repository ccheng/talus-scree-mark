# Proposed milestone roadmap

Only Milestone 0 is approved. Dates and performance values below are omitted or provisional until the Product Owner and SWE Director Assistant approve each implementation specification. Keep each milestone independently reviewable and record exact build and evidence in its PR.

| Milestone | Scope | Proposed acceptance |
| --- | --- | --- |
| M0 Foundation | Architecture, QA and research proposals, Node fixture harness | README, contributor instructions, handoff, roadmap and quality gate agree. Fresh-checkout `npm test` succeeds. Synthetic fixture provenance and limits are explicit. PR review required. |
| M1 Offline capture shell | App shell, install readiness, offline cache/update, local image capture/import | At project subpath, install online then cold-launch and capture/import in airplane mode on a named iPhone in Safari and Home Screen modes. Exercise permission denial/recovery, documented image formats and orientation, missing assets and interrupted update. Verify app never attempts to transmit capture data. |
| M2 Alignment and fixed-layout MC/NR OMR | One synthetic reference layout, registration and mark classification | Verify accepted alignment within a preregistered ROI tolerance, an exact oracle for every MC and NR fixture including blanks/decimals/zeros, and all seeded unmistakable double marks, required clipped anchors and wrong profiles routed to review or retake. On standard captures target ≥95% auto-coverage and ≤0.5% wrong among auto-accepted responses separately for MC and NR. Target scan-to-review p95 ≤3 s on the reference phone. |
| M3 Reusable per-test layouts | Versioned profiles and local profile selection/registration for varied layouts | Read at least three distinct registered layout families, including a new registered family with frozen recognition settings, and verify stable region-to-item mapping. Meet M2 accuracy/coverage targets on the frozen standard holdout, report per-family results, and block all seeded unknown or wrong-profile cases. Evaluate fallback separately before committing to support unmarked sheets. |
| M4 Review, grading and export | Corrections, key entry, local persistence, versioning and CSV/JSON exports | Pass all preregistered grade/precision/key-oracle and audit-roundtrip cases. Preserve raw results through correction, rescan, reopen and export. Unkeyed or unresolved items show explicit status. Verify deletion/quota behavior, CSV interpretation and local export on iPhone. |
| M5 Optional handwriting and comparison | Same-origin offline CNN, local comparison and review | Target ≥90% exact clear four-character tokens on oracle crops, with full-pipeline recognition reported separately. Route every seeded bubble/handwriting mismatch or unsupported symbol to review. Demonstrate bubble-only flow when model files are missing. Target optional OCR p95 ≤5 s on approved reference hardware. Keep handwriting advisory until a later decision based on measured risk. |
| M6 Pilot and hardening | Workflow reliability, readability, latency and data lifecycle | Process a batch of seven separate mock answer sheets with reconnect/relaunch interruption. Reconfirm metrics, cold/warm performance, review load, privacy checks and a local backup/restore drill on named phones. Agree on pilot thresholds and any production-origin approval before handling student data. |

For M2 and later, specify fixture counts and per-stratum denominators, calibrate only on the calibration split, and use a protected held-out set. The performance targets are proposed engineering gates. The sample size and uncertainty determine how broadly the results can be interpreted. See [research and benchmarks](docs/RECOGNITION_RESEARCH.md).
